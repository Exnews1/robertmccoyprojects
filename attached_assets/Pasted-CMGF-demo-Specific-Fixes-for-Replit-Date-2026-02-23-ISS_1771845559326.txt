ISSUE 1: "Open Full View" Button Opens Blank Page (P1 — Critical)

Root Cause

The onClick handler is:

Plain Text


() => { const n = window.open("", "_blank"); n && (n.document.write(e), n.document.close()) }



The variable e is captured from the React component's closure. The problem is that modern browsers block document.write() on cross-origin or blank popup windows when the popup is opened with an empty URL string "". The popup opens, but the document.write(e) call is either silently blocked or the window reference n is null due to popup blockers.

Fix (Two Options — Pick One)

Option A (Recommended): Use a Blob URL instead of window.open + document.write

Replace the onClick handler with:

Plain Text


const openFullView = (htmlContent) => {
  const blob = new Blob([htmlContent], { type: 'text/html' });
  const url = URL.createObjectURL(blob);
  window.open(url, '_blank');
  // Optional: revoke after delay to free memory
  setTimeout(() => URL.revokeObjectURL(url), 10000);
};



This creates a local blob URL that the browser treats as same-origin, so the HTML renders correctly.

Option B: Use a data URI

Plain Text


const openFullView = (htmlContent) => {
  const encoded = encodeURIComponent(htmlContent);
  window.open('data:text/html;charset=utf-8,' + encoded, '_blank');
};



Note: data URIs have a size limit (~2MB) and some browsers block them. Option A is more reliable.




ISSUE 2: Dashboard Tab Not Loading Initially (P2 — Important)

Root Cause (Diagnosed)

The Dashboard tab IS working — it loads correctly after clicking it. The issue is that when the user first clicks "SM Demo" and lands on the SM Results tab, the Dashboard tab appears greyed out or inactive until explicitly clicked. This is a UX perception issue, not a functional bug.

Fix

Make the Dashboard tab auto-activate (or at minimum visually indicate it has content) after the SM Demo run completes:

Plain Text


// After SM Demo completes and state is set, auto-navigate to Dashboard
// OR show a badge/indicator on the Dashboard tab
setActiveTab('dashboard'); // or equivalent state setter



Alternatively, add a "View Dashboard →" button at the bottom of the SM Results panel that navigates to the Dashboard tab.




ISSUE 3: AI Explanation Text Not Visible in ISR Case Detail (P3 — Minor)

Root Cause

In the ISR Queue case detail view, the "AI Explanation" bar (amber/gold background) has text that is not visible. This is a CSS color contrast issue — the text color is likely white or light grey on a light amber background.

Fix

In the ISR case detail component, find the AI explanation bar and ensure text color is dark:

CSS


.ai-explanation-bar {
  background-color: #FFF3CD; /* light amber */
  color: #212529; /* dark text — NOT white */
  border-left: 4px solid #F4A623;
  padding: 12px 16px;
}

The amber "Demonstration Data" banner at the top of ISR Queue and Audit Trail is correct and should be kept. However, it would be stronger if it read:


"⚠ Demonstration Data — All records shown are synthetic, generated for framework demonstration purposes. No real service member data is used."

This is already close to what exists. Just verify the full disclaimer text is visible and not truncated on mobile.

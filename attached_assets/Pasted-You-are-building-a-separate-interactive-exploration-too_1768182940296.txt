You are building a separate interactive exploration tool for my website robertmccoyprojects.com.

This is a CONCEPTUAL, NON-PRODUCTION demonstration of document-grounded exploration over a curated research library. It is not a chatbot, not a policy interpreter, and not an advisory system.

The system must support semantic exploration of approximately 100 curated research entries. Each entry already includes a short, human-written summary (2–5 sentences). The AI must ONLY operate over these summaries. Full documents must never be ingested or interpreted.

--------------------------------------------------
CORE REQUIREMENTS
--------------------------------------------------

1) Data Model
Implement a data schema with the following fields:
- id (string, unique)
- title
- authors
- organization
- year
- document_type
- summary (this is the ONLY field used for embeddings)
- topics (array of strings)
- url (link to full document)
- source_label
- visibility
- created_at

Embeddings must be computed ONLY from the summary field.
Store embeddings separately from metadata.

--------------------------------------------------
2) Backend
--------------------------------------------------

- Use Node.js or Python (your choice).
- Load all library entries at startup.
- Precompute embeddings once and cache them.
- Implement a POST endpoint:

POST /api/search
Input:
{
  "query": "string"
}

Output:
{
  "results": [
    {
      "id": "...",
      "title": "...",
      "summary": "...",
      "year": 2024,
      "document_type": "...",
      "source_label": "...",
      "url": "...",
      "relevance": "High | Medium | Low"
    }
  ]
}

- Retrieval must use cosine similarity.
- Return top 5 results.
- No external knowledge.
- No learning from queries.
- Stateless requests only.

--------------------------------------------------
3) Frontend
--------------------------------------------------

- Single page: “Reference Library Explorer”
- Query input labeled: “Explore the research library”
- Placeholder examples:
  “Evidence on automation and workforce transition”
  “Governance constraints in AI decision systems”
- Button label: “Explore Library”

Results must display:
- Title
- Summary text
- Source label
- Year
- “View Source →” link (opens external document)

--------------------------------------------------
4) Governance & Safety (Non-negotiable)
--------------------------------------------------

- No generative answers
- No chat UI
- No personalization
- No storage of user queries
- No analytics during demo
- Visible notice:
  “This tool supports discovery of relevant sources. Interpretation remains with the reader.”

--------------------------------------------------
5) Design Constraints
--------------------------------------------------

- Clean academic UI
- No conversational language
- No AI metaphors
- Treat the system as an index, not an assistant

--------------------------------------------------
6) Deliverables
--------------------------------------------------

- Working search interface
- Embedded summaries only
- Clear separation between metadata and embeddings
- README explaining boundaries and design intent

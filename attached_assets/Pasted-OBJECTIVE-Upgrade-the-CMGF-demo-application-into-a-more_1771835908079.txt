OBJECTIVE
Upgrade the CMGF demo application into a more autonomous, high-impact conference demonstration system that simulates intelligent workflow orchestration while remaining governed, bounded, and deterministic.

The system must NOT introduce unbounded autonomous decision making. All outputs must continue to originate from the existing CMGF rules engine and governance logic.

Your role is to act as a senior full-stack engineer and AI systems architect working inside this existing Replit project.

PRIMARY GOALS

1. Build an internal orchestration layer that simulates Manus-style autonomy using our own stack.
2. Enable one-click scenario generation, execution, and reporting.
3. Improve demo flow and perceived sophistication for conference presentation.
4. Maintain governance-first architecture (human in the loop, deterministic rules, transparency).
5. Create reusable infrastructure for future ISR and research outputs.

SYSTEM CONTEXT

Existing stack includes:

* React frontend
* Express backend
* PostgreSQL with Drizzle ORM
* CMGF rules engine
* AI Advisor Chat
* Reference Explorer (RAG)
* Data visualization components
* Scenario inputs already present
* Conference demo focus: military education and career pathways

Do NOT rewrite the application from scratch. Extend it modularly.

PHASE 1 — SCENARIO ORCHESTRATION ENGINE

Create a backend orchestration module that can:

* Generate synthetic service member profiles
* Accept parameter overrides
* Call the CMGF rules engine
* Store results
* Return structured outputs

Add endpoint:

POST /api/orchestrator/run-scenario

Request body:

{
profileType: string,
overrides?: object,
generateReport?: boolean
}

Response:

{
scenarioId,
inputs,
outputs,
explanation,
visualData,
reportUrl?
}

Create at least 5 built-in synthetic profile templates:

* Early Career Enlisted
* Mid Career Enlisted with Credits
* Officer Transition
* Deployed Service Member
* High Constraint / Funding Limited Case

Profiles should include realistic variability.

PHASE 2 — ONE CLICK DEMO MODE

Create a “Demo Mode” control panel in the frontend that allows:

Buttons:

* Generate Scenario
* Run Analysis
* Show Dashboard
* Export Report
* Generate 10 Case Simulation

This should feel intelligent and automated.

Use loading states and progress indicators to enhance perceived autonomy.

PHASE 3 — REPORT GENERATION SYSTEM

Create automated report templates:

1. Service Member Pathway Report (PDF or HTML export)
2. ESO Advisory Summary
3. Leadership Brief Snapshot

Reports must include:

* Inputs summary
* Constraint analysis
* Feasibility signals
* Recommended pathways
* Missing data flags
* Governance statement footer

Add endpoint:

POST /api/reports/generate

PHASE 4 — MULTI CASE SIMULATION / ISR FOUNDATION

Create simulation endpoint:

POST /api/orchestrator/run-batch

Capabilities:

* Run 10–50 synthetic cases
* Aggregate outputs
* Return summary statistics
* Identify common constraint triggers
* Produce visualization-ready data

This will support ISR concepts later.

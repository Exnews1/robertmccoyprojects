Build a Python FastAPI web application called "Credential Sequencing Engine (CSE)".

The system must demonstrate the following architecture:

INPUT → DATA SOURCES → BINDING RULES → OUTPUT → AUDIT LOG

This is a rule-based system. It must NOT use predictive modeling, machine learning, or automated eligibility scoring.

-----------------------------------
FUNCTIONAL REQUIREMENTS
-----------------------------------

1. User Input Form
- Career Goal (dropdown: Cyber Threat Analyst, SOC Analyst, Cloud Security Analyst)
- Current Certifications (multi-select)
- Years of Experience (numeric)
- Degree Status (None, Associate, Bachelor, Master)

2. Source Registry Layer
Create a JSON file called source_registry.json that includes:
- NICE Framework role references (mock snapshot)
- O*NET role summary (mock snapshot)
- Certification pathway data (CompTIA-style snapshot)
- Experience norms (job posting mini corpus summary)

Each source must have:
- source_name
- description
- date_snapshot
- citation_note

3. Role Dataset
Create role_data.json structured like:

{
  "cyber_threat_analyst": {
    "foundation_cert": ["CompTIA Security+"],
    "intermediate_cert": ["CompTIA CySA+"],
    "advanced_cert": ["CASP+", "CISSP (experience required)"],
    "experience_required_years": 2,
    "experience_paths": [
      "Military cyber operations",
      "Security Operations Center roles",
      "Cybersecurity internships",
      "Documented home lab projects"
    ],
    "nice_reference": "PR-CDA-001",
    "onet_reference": "15-1212.00"
  }
}

4. Binding Rules Engine
Create a Python module rules_engine.py with transparent deterministic logic:

Rules:
- If user has no foundational cert → recommend foundation_cert
- If foundation present but no intermediate → recommend intermediate_cert
- If intermediate present and experience < required → recommend experience building
- If experience ≥ required → suggest advanced_cert (conditional note)

Each rule must:
- Log when it fires
- Be visible in output as "Rule Triggered"

5. Output Panel
Display:
- Suggested Credential Stack (ordered)
- Experience Advisory Note
- Transparent Explanation
- Evidence Panel

6. Evidence Panel
Display:
- NICE reference used
- O*NET reference used
- Source snapshot date
- Rules triggered
- System disclaimer

7. Governance Disclaimer
Add this visible text in output:

"This system provides structured decision-support information. It does not determine eligibility, guarantee employment outcomes, or replace professional advising. Users are responsible for verifying credential requirements."

8. Audit Log
Create a simple log file (audit_log.txt) that records:
- Timestamp
- User input
- Rules triggered
- Output generated

-----------------------------------
ARCHITECTURE REQUIREMENTS
-----------------------------------

- Use FastAPI backend
- Simple HTML/CSS frontend (no complex frameworks)
- Clean folder structure:

/app
  main.py
  rules_engine.py
  role_data.json
  source_registry.json
  templates/
  static/

-----------------------------------
CONSTRAINTS
-----------------------------------

- No predictive modeling
- No external APIs
- No storing PII beyond session
- All outputs must cite sources
- Code must be readable and modular

-----------------------------------
GOAL
-----------------------------------

This is a functional governance-aligned prototype demonstrating transparent credential sequencing with data provenance.

Build a clean, expandable foundation suitable for future role additions.

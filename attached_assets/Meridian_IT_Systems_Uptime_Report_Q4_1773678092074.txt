CRM OUTAGE POST-INCIDENT REVIEW

On November 14, the CRM database experienced a failover event
triggered by storage controller firmware error. The primary database
became unresponsive at 14:23 EST. Automated failover to the secondary
node initiated at 14:31 but required manual intervention due to
replication lag. Service was fully restored at 18:42 EST.

Root Cause: Storage controller firmware version 3.2.1 contained a
known memory leak triggered under high write conditions.

Corrective Actions (all completed):
  - Firmware updated to version 3.2.4 on all storage controllers
  - Replication monitoring alerts tightened from 30-second to
    5-second lag threshold
  - Failover runbook updated with manual intervention procedures

------------------------------------------------------------------------

RECOMMENDATIONS

1. Upgrade CRM database to active-active cluster configuration
   to eliminate single-point-of-failure risk (Q2 2025 budget request
   submitted).
2. Implement automated failover testing on a monthly basis for all
   Severity 1 systems.
3. Increase storage monitoring granularity to detect firmware-related
   anomalies before they trigger outages.

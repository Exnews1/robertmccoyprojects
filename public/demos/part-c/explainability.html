Understanding Advisory Signals — Why They Appear, Not What to Do

This screen provides detailed explanations for each advisory signal generated by the AI mediation layer. Every explanation focuses on the reasoning behind signal generation—describing why a signal appears based on data sources, constraint analysis, and processing logic. No explanations include recommendations, actions, or judgments.

Explainability Principles

Why, Not What
Every explanation describes why a signal was generated based on input data, constraint conflicts, or policy references. No explanation tells the user what action to take or what decision to make.
Source Traceability
Every signal traces back to specific data sources, policy documents, or processing stages. Version numbers, timestamps, and database references are included for audit purposes.
Processing Transparency
The logic used to generate each signal is documented, including which processing stage produced the signal and what inputs were analyzed. No hidden or opaque processing steps.
No Judgment Language
Explanations avoid evaluative language such as "good," "bad," "optimal," "suboptimal," "recommended," or "discouraged." Signals are descriptive, not prescriptive.

Explanation Methodology

How Explanations Are Generated
Every advisory signal generated by the AI mediation layer is accompanied by a structured explanation. These explanations are not manually written—they are automatically generated using a templated methodology that ensures consistency, transparency, and traceability.
Step 1: Signal Classification
Each signal is classified by type (constraint conflict, missing information, trade-off, incompatibility, compliance check). Classification determines which explanation template is used.
Step 2: Data Source Extraction
The system extracts all data sources, policy references, and database fields that contributed to signal generation. Version numbers, timestamps, and record IDs are captured.
Step 3: Processing Stage Documentation
The explanation identifies which processing stage (Input Normalization, Constraint Analysis, Scenario Construction, etc.) produced the signal and what logic was applied.
Step 4: Non-Event Documentation
The explanation explicitly documents what the system did NOT do—no recommendations, no rankings, no predictions, no automated actions.
Step 5: Human Handoff Context
The explanation concludes with a statement about what human interpretation is required, emphasizing that decision authority remains with human reviewers.
Explanation Quality Standards
Completeness: Every signal includes all five explanation components (classification, data sources, processing stage, non-events, human context)
Traceability: All data sources, policy references, and processing stages are explicitly documented with version numbers and timestamps
Neutrality: Explanations avoid evaluative language and do not suggest actions, preferences, or judgments
Auditability: All explanation components are logged and can be reviewed for compliance verification
Accessibility: Explanations are written in clear, non-technical language accessible to human reviewers without specialized AI knowledge
